## 一、总体目标

为 QuillEditorPanel 和 VditorEditorPanel 添加**右下角拖拽手柄**，允许用户通过拖拽动态调整面板的宽度和高度，同时编辑区域自动填充剩余空间。

---

## 二、模块设计

### 2.1 新建 `src/ui/behaviors/Resizable.js`

**职责**：为面板元素提供拖拽调整大小的功能

**核心功能**：
- 在目标元素右下角创建拖拽手柄（resize handle）
- 监听鼠标事件（mousedown/mousemove/mouseup）
- 计算拖拽距离，动态更新元素的 `width` 和 `height`
- 支持设置最小/最大尺寸限制
- 提供清理函数，移除手柄和事件监听

**API 设计**：
```javascript
const Resizable = {
    /**
     * 为元素添加拖拽调整大小功能
     * @param {HTMLElement} el - 目标元素
     * @param {Object} options - 配置选项
     * @param {number} [options.minWidth=400] - 最小宽度
     * @param {number} [options.minHeight=300] - 最小高度
     * @param {number} [options.maxWidth] - 最大宽度（可选）
     * @param {number} [options.maxHeight] - 最大高度（可选）
     * @param {Function} [options.onResize] - 调整大小时的回调函数
     * @returns {Function} 清理函数
     */
    make(el, options = {})
}
```

**实现细节**：
1. 创建一个 `div` 作为拖拽手柄，样式为右下角小三角或方形区域
2. 手柄样式：`position: absolute; right: 0; bottom: 0; width: 15px; height: 15px; cursor: nwse-resize;`
3. `mousedown` 时记录初始鼠标位置和元素尺寸
4. `mousemove` 时计算差值，更新元素的 `width` 和 `height`
5. `mouseup` 时结束拖拽，可选保存尺寸到 Config
6. 返回清理函数，用于移除手柄和事件监听

**文件结构**：
```javascript
const Resizable = (() => {
    return {
        make(el, options = {}) {
            // 1. 创建拖拽手柄元素
            // 2. 绑定 mousedown 事件到手柄
            // 3. 在 mousedown 中绑定 document 的 mousemove/mouseup
            // 4. mousemove 中计算并更新尺寸
            // 5. mouseup 中清理事件
            // 6. 返回清理函数
        }
    };
})();
```

**关键逻辑**：
- 拖拽时限制最小尺寸（防止面板过小）
- 拖拽时限制最大尺寸（可选，防止超出屏幕）
- 每次尺寸变化时调用 `options.onResize(newWidth, newHeight)` 回调

  ```javascript

      // ... 其他样式
  }
  ```

**修改点 2：在 `onBodyReady` 中初始化 Resizable**
- 在 body 内容渲染完成后，调用 `Resizable.make(panelInstance.element, {...})`
- 配置最小尺寸：`minWidth: 400`, `minHeight: 350`
- 配置 `onResize` 回调，用于更新 Quill 编辑器布局

**修改点 3：调整 Quill 编辑器高度策略**
- 移除 `initQuillEditor` 中的固定 `minHeight: '200px'`
- 改为使用 CSS `flex: 1` 或动态计算高度：
  ```javascript
  // 计算可用高度
  const panelRect = panelInstance.element.getBoundingClientRect();
  const headerHeight = 50;  // header 约 50px
  const bodyPadding = 24;   // body padding-top + padding-bottom
  const titleInputHeight = 40;
  const tagsHeight = 40;
  const timestampHeight = 30;  // 如果有时间戳
  const footerHeight = 30;
  
  const availableHeight = panelRect.height - headerHeight - bodyPadding - titleInputHeight - tagsHeight - timestampHeight - footerHeight;
  
  qlContainer.style.height = availableHeight + 'px';
  qlEditor.style.height = availableHeight + 'px';
  ```

**修改点 4：在 `onResize` 回调中更新 Quill**
- 当面板尺寸变化时，调用 `quillInstance.update()` 重新计算布局
- 重新计算并设置 `ql-container` 和 `ql-editor` 的高度

**修改点 5：在 `close` 函数中清理 Resizable**
- 添加 `resizeCleanup` 变量存储清理函数
- 在 `close` 函数中调用 `resizeCleanup()`

## 五、技术难点与解决方案

### 难点 1：Quill 编辑器高度自适应
**问题**：Quill 的 `ql-container` 和 `ql-editor` 需要明确的高度值

**解决方案**：
- 使用 JavaScript 动态计算可用高度
- 在 `onResize` 回调中重新计算并设置高度
- 调用 `quillInstance.update()` 触发内部重算

### 难点 2：Vditor 编辑器高度动态调整
**问题**：Vditor 的 `height` 是初始化参数，后续修改可能需要重建实例

**解决方案**：
- 优先尝试直接修改 `vditorInstance.element.style.height`
- 如果无效，则销毁旧实例并用新高度重建（保存当前内容）
- 调用 Vditor 的内部方法触发重绘（如 `vditorInstance.setPreviewMode('editor')`）

### 难点 3：面板尺寸与内容溢出
**问题**：面板过小时，内容可能溢出或编辑器无法正常显示

**解决方案**：
- 设置合理的最小尺寸（`minWidth: 400`, `minHeight: 350`）
- 使用 CSS `overflow: hidden` 或 `overflow: auto` 处理溢出
- 在编辑器区域添加 `min-height` 保证基本可用性

### 难点 4：拖拽手柄的视觉反馈
**问题**：用户需要知道哪里可以拖拽调整大小

**解决方案**：
- 使用明显的拖拽手柄样式（右下角小三角）
- 鼠标悬停时改变光标为 `nwse-resize`
- 拖拽时显示半透明的尺寸提示（可选）

## 六、预期效果

1. **初始状态**：面板打开时有合理的默认尺寸（宽度 520-560px，高度 500-550px）
2. **拖拽调整**：用户可以通过右下角手柄自由调整面板大小
3. **编辑区域自适应**：无论面板多大，编辑区域始终填充剩余空间
4. **尺寸限制**：面板不能拖拽过小（最小 400x350px），保证内容可读性
5. **状态保持**：可选保存用户调整的尺寸，下次打开时恢复
