# Quill 编辑器在油猴脚本中无法加载的问题与修复方案

> **日期**: 2026-05-31  
> **项目**: bilibiliv18 油猴脚本  
> **问题文件**: `src/ui/views/QuillEditorPanel.js`

---

## 一、问题描述

在油猴脚本中动态加载 Quill 富文本编辑器后，编辑器面板显示为空白，Quill 始终无法初始化。

### 症状

- 脚本通过 `document.head.appendChild(script)` 成功加载了 Quill 的 JS/CSS 资源
- 在浏览器控制台中执行 `window.Quill` 可以看到 Quill 已存在
- 但油猴脚本内部检测 `window.Quill` 始终为 `undefined` / `false`
- 编辑器容器内没有任何内容渲染

---

## 二、根本原因：油猴脚本沙箱隔离

### 什么是沙箱隔离？

当你使用 `@grant` 声明了任何 GM API（如 `GM_registerMenuCommand`、`GM_addStyle`、`GM_setValue` 等）时，Tampermonkey 会将你的脚本运行在一个**沙箱环境**中。

在沙箱环境中：
- 你脚本里的 `window` **不是**页面的真实 `window`
- 它是一个**代理对象**，只暴露部分属性和方法
- 页面真实 `window` 上的变量（如 `window.Quill`）在沙箱中**不可见**

### 问题发生的过程

```
1. 油猴脚本执行 document.head.appendChild(script) 加载 Quill
   ↓
2. Quill 脚本在【页面真实上下文】中运行
   ↓
3. Quill 构造函数被设置到【页面真实 window.Quill】上
   ↓
4. 油猴脚本在【沙箱环境】中检测 window.Quill
   ↓
5. 沙箱的 window 是代理，看不到页面真实 window.Quill
   ↓
6. 结果：window.Quill 始终为 false，初始化失败 ❌
```

### 图解

```
┌─────────────────────────────────────────┐
│           页面真实上下文                 │
│                                         │
│   window.Quill = function Quill() {...}  │  ← Quill 在这里
│                                         │
│  ┌───────────────────────────────────┐  │
│  │     油猴脚本沙箱环境               │  │
│  │                                   │  │
│  │   window.Quill === undefined  ❌   │  │  ← 沙箱看不到外面
│  │                                   │  │
│  └───────────────────────────────────┘  │
│                                         │
└─────────────────────────────────────────┘
```

## 三、修复方案

### 步骤 1：添加 `@grant unsafeWindow` 权限

在用户脚本头部元数据区添加 `@grant unsafeWindow`：

```javascript
// ==UserScript==
// @name         B站自定义倍速油猴脚本简洁版
// @namespace    http://tampermonkey.net/
// @version      v2.0
// @description  可以自定义bilibili 播放倍速...
// @author       小明
// @license MIT
// @icon         chrome://favicon/http://www.bilibili.com/
// @match        *://www.bilibili.com/*
// @grant        GM_registerMenuCommand
// @grant        GM_setValue
// @grant        GM_getValue
// @grant        GM_addStyle
// @grant        unsafeWindow          // ← 新增这一行
// @run-at       document-end
// ==/UserScript==
```

> **`unsafeWindow` 是什么？**  
> 它是油猴脚本提供的一个特殊对象，指向**页面的真实 `window`**。通过它，你可以访问页面上下文中定义的全局变量和函数。

### 步骤 2：创建 `getQuill()` 辅助函数

在你的代码中添加一个辅助函数，优先使用 `unsafeWindow` 获取 Quill：

```javascript
// 获取 Quill 构造函数（兼容沙箱环境）
function getQuill() {
    return (typeof unsafeWindow !== 'undefined' && unsafeWindow.Quill)
        ? unsafeWindow.Quill
        : window.Quill;
}
```

> **为什么这样写？**  
> - 先检查 `unsafeWindow` 是否存在且有 `Quill`，如果有就用它
> - 如果没有 `unsafeWindow`（比如非油猴环境），回退到 `window.Quill`
> - 这样代码既能在油猴脚本中运行，也能在普通网页中运行

### 步骤 3：替换所有 `window.Quill` 为 `getQuill()`

**修改前（错误）：**
```javascript
function loadQuillResources() {
    return new Promise((resolve, reject) => {
        if (window.Quill) {   // ❌ 沙箱中永远为 false
            resolve();
            return;
        }
        // ...
    });
}

function initQuillEditor(containerEl) {
    if (!window.Quill) return;  // ❌ 这里也会失败
    const quill = new window.Quill(containerEl, { ... });
}
```

**修改后（正确）：**
```javascript
function loadQuillResources() {
    return new Promise((resolve, reject) => {
        if (getQuill()) {       // ✅ 通过 unsafeWindow 获取
            resolve();
            return;
        }
        // ...
    });
}

function initQuillEditor(containerEl) {
    const Quill = getQuill();
    if (!Quill) return;         // ✅ 正确检测
    const quill = new Quill(containerEl, { ... });
}
```

## 四、关键概念总结

| 概念 | 说明 |
|------|------|
| `@grant` | 声明油猴脚本需要的 API 权限。**只要使用了 `@grant`，脚本就会运行在沙箱中** |
| 沙箱环境 | 油猴脚本的隔离运行环境，脚本中的 `window` 是代理对象 |
| `window`（沙箱中） | 代理对象，只能访问部分页面属性，**看不到页面全局变量** |
| `unsafeWindow` | 指向页面真实 `window` 的引用，可以访问页面所有全局变量 |
| `@grant unsafeWindow` | 声明需要使用 `unsafeWindow` 的权限 |

## 五、新手常见问题

### Q1: 我没有使用 `@grant`，会有这个问题吗？

**不会。** 如果你没有声明任何 `@grant`，油猴脚本会直接运行在页面上下文中，`window` 就是真实的 `window`，不会有沙箱隔离问题。

### Q2: 我用了 `@grant none`，会有这个问题吗？

**不会。** `@grant none` 表示不使用任何 GM API，脚本运行在页面上下文中。

### Q3: 什么时候必须用 `unsafeWindow`？

当你同时满足以下两个条件时：
1. 使用了 `@grant` 声明了 GM API（触发沙箱模式）
2. 需要访问页面全局变量（如 `window.Quill`、`window.jQuery`、`window.$` 等）

### Q4: 动态加载的第三方库一定要用 `unsafeWindow` 吗？

**是的。** 通过 `document.createElement('script')` 动态加载的库，会在页面真实上下文中执行，其全局变量会挂载到页面真实 `window` 上。沙箱中的 `window` 看不到这些变量，必须通过 `unsafeWindow` 访问。

### Q5: 可以直接用 `unsafeWindow.Quill` 吗？为什么还要写 `getQuill()` 函数？

可以。但写成函数的好处是：
- 代码更清晰，意图明确
- 方便后续维护，如果获取逻辑变化只需改一处
- 兼容非油猴环境（回退到 `window.Quill`）
